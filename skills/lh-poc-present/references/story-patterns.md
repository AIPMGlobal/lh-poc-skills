# 컨설팅 스타일의 보고와 장표

컨설팅 스타일은 먼저 판단할 결론을 제시하고, 증거와 조건을 통해 그 결론을 설명하는 방식이다. 전문 용어, 고정 장수, 정해진 프레임워크 이름을 나열할 필요는 없다.

## 보고 목적에 맞게 흐름을 고른다

- **성과 공유·교육 결과:** 어떤 문제를 다뤘고 → 어떻게 바꿨고 → 무엇을 확인했고 → 어떤 의미가 있으며 → 다음에 무엇을 할지. 실제 결재 요청이 없으면 다음 검증·적용 제안으로 끝낸다.
- **시범 적용·투자 판단:** 권고와 이유 → 중요한 문제와 현재 대안 → 제안 방식과 검증 → 필요한 비용·운영 부담·판단 조건 → 한정된 다음 적용과 판단 기준.
- **확대 판단:** 현재 범위에서 확인한 효과 → 재사용할 부분과 대상별 차이 → 추가 비용·운영 책임·통제 조건 → 단계별 확대와 재검토 기준.
- **성과가 약하거나 실패한 과제:** 시도와 결과 → 확인한 것과 얻은 것 → 계속·수정·축소·중단 선택지 → 다음 판단에 필요한 최소 검증.

불확실성과 실패가 생긴 조건의 상세는 구두 보충과 숨김 부록에 두고, 화면에는 확인한 결과·필요한 조건·선택지를 싣는다. 교육생이 화면에 넣기를 원하면 따른다.

이는 논리의 예시이며 고정된 장별 목차가 아니다. 사용자 목차를 우선하고, 질문이 겹치면 합치며, 요청 범위를 넘어 사업계획서 전체를 만들지 않는다. 여러 과제를 묶을 때 실제 시스템 관계가 없는 역할 연결은 개념도라고 명시한다.

## 목차보다 먼저 장의 역할을 결정한다

내부 초안에 각 장의 `판단 질문 / 답 / 새 근거 / 제목`을 적는다. 예를 들어 ‘이 결과를 업무에 사용할 수 있는가?’에는 실제 출력과 사용 범위가 답이 된다. ‘어떻게 만들었는가?’를 모든 장의 숨은 질문으로 삼지 않는다.

- 결론 요약은 전체 주장을 예고하고, 뒤 장은 그 주장을 입증한다. 요약 문구만 다른 배치로 반복하는 장은 제거한다.
- ‘조직 가치’, ‘확장 가능성’, ‘향후 계획’이 같은 근거로 같은 기대를 말하면 하나로 합친다. 서로 다른 판단이 필요한 경우에만 나눈다.
- 성과 보고에는 결과를 보여주는 증거를 일찍 둔다. 제작 과정과 모델·노드 설명은 결과를 이해하거나 적용 판단을 하는 데 필요한 만큼만 남긴다.
- 실제 출력이 없거나 보안상 공개할 수 없으면 검증 기록·비식별 요약 등 적절한 증거를 고른다. 없는 사례나 화면을 실제 결과처럼 만들지 않는다.
- 대표 사례 하나의 개선과 전체 결과의 개선은 별개다. 좋은 출력은 크게 보여주되 그 사례로 전체 통과율·업무 효과를 대신 증명하지 않는다.

## 결론과 근거

핵심 문장에는 자료가 뒷받침하는 변화와 다음 판단을 담는다. 추상적인 '혁신·시너지·경쟁력 강화'만으로 끝내지 않는다. 각 근거는 다른 역할을 맡게 한다. 예: 실제 업무 사례 / 비교 결과 / 적용·운영 조건.

가치 설명을 요청받았으면 **확인된 업무 변화와 그 조직적 의미를 분명하게 설명**한다. 제목과 본문에 '확인 필요·추가 검증'을 쓰지 않는다. 제공 자료로 확인할 수 있는 기능·역할·업무 방식의 변화는 구체적으로 말하고, 아직 입증하지 못한 사업 결과는 기대 효과로 구분한다.

수치의 성격과 산정 조건은 하단 출처 줄에 한 번 적는다. 자료 수집 작업은 작성자 확인사항으로 모은다. 한계와 남은 일은 화면이 아니라 발표자 노트의 구두 보충과 숨김 부록에 둔다. 발표자는 질문이 나오면 숨기지 않고 답한다.

사업 효과가 아직 확인되지 않았다면 제목에서 실적으로 쓰지 않고 기대 효과나 목표로 쓴다. 단순한 규칙·절차 개선이 충분할 때는 AI의 추가 기여를 구두 보충에 정리해 둔다.

### 제목 예시 — 모두 설명을 위한 가상 사례

- 주제만 있는 제목: `AI 도입 효과`
- 구체적인 결론: `같은 20건에서 담당자 수정이 필요한 답변이 줄었습니다`
- 범위를 좁혀 말할 때: `시범 업무 20건에서 확인한 변화입니다`
- 사업 의미를 말할 때: `검토 이력을 공유해 다음 담당자가 판단 근거를 이어받습니다`
- 초기 가설 단계: `검토 시간을 줄일 수 있는지 한 업무부터 확인합니다`

모든 장을 주장형으로 강제하지 않는다. 소개·구조·범위·실행 화면은 명확한 주제형 제목도 쓸 수 있다.

## 장별 구성 형식

교육생과 처음 논의할 때는 [대화와 구성 제안](dialogue-workflow.md)의 `장 / 이야기할 내용 / 들어갈 근거` 세 열 표를 쓴다. 아래 다섯 열은 제작을 위한 내부 메모이며 첫 응답에서 모두 출력할 필요는 없다.

| 장 | 판단 질문 | 제목·핵심 메시지 | 새 근거·도식 | 출처 |
|---|---|---|---|---|
| 실제 순서 | 이번 장에서 판단할 것 | 청중이 기억할 한 가지 | 앞 장에 없던 출력·비교·범위·조건 | 파일·장/절·기록 위치와 확인 상태 |

장수는 사용자 요청과 자료의 양에 맞춘다. 지정이 없으면 중복 없이 초안을 제안하고 장수를 확정 사실로 취급하지 않는다. 같은 화면·수치를 반복해 페이지를 늘리지 않는다.

- 전후 흐름도는 바뀐 단계와 사람의 확인 지점을 표시한다.
- 대표 사례는 입력·기대 결과·실제 결과·사람의 수정 또는 판단을 연결한다.
- 효과 표는 현재·개선 후·조건을 나란히 둔다. 업무 규모와 효과 금액을 같은 열로 합치지 않는다.
- 확산 도식은 현재 적용·다음 시범·장기 가능 범위를 시각적으로 구분한다.
- 표·그림의 제목은 결과를 말하고, 수치의 조건은 하단 출처 줄에 둔다.

## 경영진에게 보여줄 것과 작성자가 확인할 것

청중용 본문에는 결론, 결정에 필요한 증거, 다음 제안을 넣는다. 한계, 원시 평가 상세, 실패 사례는 노트의 구두 보충과 숨김 부록으로 보낸다. 작성자 확인사항에는 누락 자료와 모순 해결을 적되, 확인 전 확정 문장을 완성본처럼 내보내지 않는다.

평가를 다룰 때 본문에서는 통과한 결과와 결과물의 쓸모를 설명한다. 채점 코드, 중복 평가 항목, 실행별 원시 행, 실패·미측정 건은 노트와 숨김 부록으로 옮긴다. 발표자가 질문에 답할 수 있도록 구두 보충에 실패 건과 표본 조건을 빠짐없이 적어 둔다.

예상 질문은 이번 추천을 좌우하는 내용으로 고른다. 다음 질문을 모두 기계적으로 출력하지 않는다.

- 기존 방식·규칙 자동화와 비교해 AI가 추가로 기여한 부분은?
- 사람이 확인하고 수정한 뒤에도 효과가 남는가?
- 대표 사례 외에 어느 조건에서 실패하는가?
- 확보한 여력은 어디에 사용하며 실제 운영 부담은 무엇인가?
- 다른 조직에서 그대로 쓸 부분과 새로 해야 할 부분은?
- 누가 운영하고 어떤 기준에서 확대·재검토할 것인가?

## 제작 도구에 넘길 때

최종 파일 제작이 요청되면 교육생과 마지막으로 합의한 메시지·장별 내용·근거를 제작 도구에 넘긴다. 기존 디자인 양식과 고정 항목은 사용자의 요청 범위에 맞춰 보존한다. 전면 개선 요청이라면 기존 카드·목차 배치까지 고정할 필요는 없다. [장표의 증거 배치](executive-slide-design.md)에서 해당 근거에 맞는 구성만 고른다. 강의용 템플릿을 사용하더라도 실습 지시문을 임원 보고에 자동 삽입하지 않는다. 도구가 없으면 제작 완료를 주장하지 말고 편집 가능한 구성안을 제공한다.

## 한국어 표현

문장의 주체와 변화가 보이게 쓴다. 예: `선제적 가치 창출 기반 고도화`보다 `반복 검토를 줄여 담당자가 예외 판단에 집중하도록 합니다`. 어려운 기술명은 처음 등장할 때 업무 역할로 풀어 쓴다. 긴 명사 나열과 모든 장의 동일한 구호를 피한다. 한 과제의 기술 구조를 다른 과제의 필수 요건으로 복사하지 않는다.

사례는 번호만으로 부르지 말고 업무 상황이나 확인 항목으로 설명한다. 내부 자료 ID·테스트 항목 코드는 추적용 노트에 남기고, 청중용 각주는 알아볼 수 있는 문서명·날짜로 쓴다. 서식의 레이아웃 ID와 작성 안내도 최종 발표 파일에서 정리한다.
