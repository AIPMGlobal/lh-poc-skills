# 우수 발표의 설득 장치

사내 경진대회에서 좋은 평가를 받은 Agent 발표들을 읽고 공통점을 정리한 것이다. 다른 조직의 수치와 문장은 그 조직의 것이다. 우리 과제의 성과나 목표로 옮기지 않고, **무엇을 어떤 순서로 보여 줬는가**만 가져온다.

## 좋은 발표가 공통으로 한 일

| 설득 장치 | 좋은 발표가 한 방식 | 우리 구성에서 확인할 것 |
|---|---|---|
| 1. 문제를 숫자로 연다 | 건수, 시간, 인원을 먼저 제시했다 | 업무 빈도, 걸리는 사람 시간, 관여하는 인원 중 자료에 있는 것 |
| 2. 한 줄 전후 대비 | 같은 단위의 전후를 한 줄로 보여 줬다 | 같은 업무 구간, 같은 단위의 전후 한 쌍 |
| 3. 실제 화면과 시연 | 시연 영상이나 실제 화면을 본문 가운데 뒀다. 사용자가 하는 일은 '파일 올리기와 한 줄 입력'처럼 줄여 말했다 | 실제 출력 화면 한 장과 사용 순서 세 단계 |
| 4. 사람과 AI의 역할 구분 | 'AI는 자료 준비, 사람은 최종 판단'처럼 책임을 한 문장으로 말했다 | 최종 책임자, 코드와 AI와 사람이 하는 일 |
| 5. 조직 방향과 다음 단계 | 조직의 공식 방향에 연결하고 '지금 → 다음 → 이후' 단계를 보여 줬다 | LH 공식 방향 한두 개와 현재 위치가 보이는 단계 |

여기에 세 가지가 더 있었다.

- **안 하면 생기는 일.** 같은 업무 영역의 공개 사고나 지적 사례를 날짜, 규모와 함께 제시해 위험을 구체화했다. 우리 과제도 같은 업무 영역의 공개 사례가 있으면 원문을 확인해 쓴다.
- **닫는 한 문장.** 마지막 장은 요약 반복이 아니라 과제의 의미를 한 문장으로 선언했다.
- **화면에는 성과만.** 화면에 놓친 사례나 미완 항목을 올리지 않았다. 남은 과제는 '향후 방향'이라는 이름으로 앞을 보는 말로 썼다. 우리도 안 된 것은 화면이 아니라 구두 보충으로 말한다.

## 가져오지 않을 것

- 근거 없는 금액. 우리 자료에 산식과 입력이 없으면 금액을 만들지 않는다.
- 하지 않은 것을 한 것처럼 쓰는 일. 좋은 평가를 받은 발표는 대부분 이미 운영 중이었다. PoC 과제는 구현, 시험, 적용 전 단계가 섞여 있으므로 현재 위치를 표지와 단계 장에 사실대로 표시한다. 안 된 것을 화면에서 빼는 것과 없는 성과를 쓰는 것은 다르다.
- 긴 기능 목록. 기능보다 '그래서 누가 무엇을 다르게 하는가'를 앞세운다.

## LH 발표에서 특히 살릴 것

- **역할 구분을 그림으로.** 공공기관 업무는 책임 소재가 분명해야 한다. 규칙으로 정답이 정해지는 일은 코드, 읽고 쓰는 일은 AI, 책임이 따르는 판단은 사람이라는 구분을 [도식](diagrams.md)으로 보여 준다. 규칙 처리만 한 것을 'AI가 판단했다'고 쓰지 않는다.
- **현행과 개선을 같은 단위로.** PRD의 As-Is/To-Be 표가 출발점이다. 단계, 담당, 시간이 같은 기준이어야 한 줄 전후 대비가 성립한다.
- **시연은 줄이지 않는다.** 듣는 사람이 가장 오래 기억하는 부분이다. 데모 주소가 있으면 적되, 접속이 안 될 때를 대비해 핵심 화면은 캡처로도 넣는다.

## 구성 제안에 쓰는 법

첫 응답의 구성표 아래에 다섯 장치의 상태를 한 줄씩 적는다. 각 줄은 `있음 / 끌어낼 것 / 없음`으로 시작한다. 형식은 [대화와 구성 제안](dialogue-workflow.md)의 예시를 따른다.

없는 장치를 억지로 채우지 않는다. 숫자가 없으면 [근거와 규모 판단](evidence-and-scale.md)의 순서로 교육생에게서 끌어낸다. 화면이 없으면 요청하고, 받지 못하면 실제 출력을 표로 옮겨 '발췌'라고 밝힌다.
