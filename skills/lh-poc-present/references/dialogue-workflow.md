# 교육생과 발표 흐름을 함께 다듬는 방법

목표는 한 번에 그럴듯한 PPT를 출력하는 것이 아니다. 교육생이 자신의 업무와 결과를 설명하고, AI가 이를 경영진의 판단에 필요한 이야기로 정리하며, 함께 다듬은 뒤 파일로 만든다.

## 첫 응답: 읽은 자료로 구체적인 안부터 제시한다

자료에서 확인한 현재 구현·활용 상태와 가장 설득력 있는 사업적 의미를 한두 문장으로 설명한다. 경영진에게 무엇을 이해시키거나 어떤 판단을 요청할지 드러내되 실제 요청되지 않은 예산·인력 승인은 만들지 않는다. 자료를 쓴 시점과 지금의 상태가 다를 수 있으면 어느 시점 자료를 기준으로 읽었는지 첫 문장에 밝히고, 표지의 현재 위치는 교육생 답을 받은 뒤 확정한다.

그다음 아래 형식의 세 열 표를 보여준다. 아래는 12장 구성의 출발점이며 고정 목차가 아니다. 표지는 따로 두며, 아래 번호는 표지 다음 장부터 센다. 교육생의 과제명·실제 문제·산출물·업무 역할을 넣어 구체화한다. 장 제목은 대화에서 다듬을 초안으로 제시한다.

| 장 | 이야기할 내용 | 들어갈 근거 |
|---|---|---|
| 1. 핵심 요약 | 한 줄 전후 대비로 결론을 먼저 말하고, 확인한 결과·운영 방식·오늘의 요청(없으면 다음 단계)을 예고 | 같은 구간·같은 단위의 전후 한 쌍, 핵심 평가 결과 한 줄 |
| 2. 이 업무에서 먼저 해결해야 했던 문제 | 누가 어떤 작업을 반복하며 그 문제가 몇 명의 일로 번지는지 설명 | 업무 빈도, 관여 인원, 재작업이 생기는 경로 |
| 3. 문제가 생기는 지점 | 어디서 어긋나고 왜 사람이 놓치기 쉬운지 구조로 보여 줌 | 실제 업무 사례, 대조하거나 확인해야 하는 자료의 관계 |
| 4. 안 하면 생기는 일과 외부의 대응 | 같은 업무 영역의 공개 사고·제재 사례와, 다른 기업이 AI를 쓰는 방식 | 원문을 확인한 사례(기관·날짜·규모). 우리 과제와 다른 점은 구두 보충으로 |
| 5. 기존 업무를 이렇게 바꿨습니다 | 개선 전후 업무 흐름과 AI·규칙·사람의 역할을 비교 | 전후 업무 흐름, 달라진 단계, 사람의 확인 지점 |
| 6. 실제로 이렇게 씁니다 | 사용 순서 세 단계와 실제 화면을 보여 줌 | 실제 출력 화면 또는 발췌, 입력 조건, 처리 시간(사람 시간과 구분) |
| 7. 검증 결과 | 평가에서 확인한 결과 세 가지와 다음 확인 계획 | 통과/평가 건수, 통과한 항목, 처리 조건. 실패·미측정 건은 구두 보충으로 |
| 8. 조직에 생기는 효과 | 담당자 한 사람을 넘어 다음 업무와 다른 사람에게 생기는 변화를 산식과 함께 설명 | 산식의 입력(교육생에게 받은 값), 달라지는 일 |
| 9. 운영 책임 | 누가 확정하고 AI·규칙·사람이 각각 무엇을 하는지, 운영 환경 | 사람 확인 지점, 운영 환경 |
| 10. 이 변화가 LH에 갖는 의미 | 정부 정책·공사의 경영 방향과 해당 부서의 역할에 연결하고 업무에 남는 자산을 설명 | 공식 방향의 출처와 날짜, 이 과제가 하는 일 |
| 11. 다음 단계와 요청 | 현재 위치가 보이는 단계, 넓힐 수 있는 인접 업무, 필요한 결정 | 단계별 상태, 재사용할 것과 새로 정할 것, 요청 사항 |
| 12. 닫는 한 문장 | 과제의 의미를 한 문장으로 선언 | 앞 장에서 이미 보여 준 근거 세 가지 |

위 열두 장은 출발점이며 고정 목차가 아니다. 자료가 없는 장은 합치거나 뺀다. 예를 들어 공개 사례를 확인하지 못했으면 4장을 빼고, 확장 근거가 약하면 10장과 11장을 합친다. 숨김 부록 한 장에는 근거와 해석 범위를 표로 모은다.

구성표 바로 아래에 설득 장치 다섯 가지의 상태를 적는다. 각 줄은 `있음 / 끌어낼 것 / 없음` 중 하나로 시작한다. '없음'은 물어도 받지 못한 경우다. 그래서 첫 응답에서는 '있음'과 '끌어낼 것'만 쓴다. 한 장치의 일부만 있으면 `있음(일부)`로 시작하고 있는 것과 끌어낼 것을 한 줄에 나눠 적는다. LH 방향 문구는 교육생에게 묻는 항목이 아니라 스킬이 공식 원문에서 확인할 항목이다. 아래는 형식 예시이며 값은 다른 과제에 옮기지 않는다.

```
설득 장치 점검
- 문제의 숫자: 있음 — 매월 1회, 자료 9종, 회차당 약 4시간
- 한 줄 전후 대비: 끌어낼 것 — 현행 4시간은 있음. 바뀐 뒤 검토까지 포함한 시간 (아래 질문에서 요청)
- 실제 화면: 있음 — 공개 데모 페이지와 결과 Excel
- 역할 구분: 있음 — 코드가 통합과 분류, AI가 보고서 문안, 담당자가 검토와 확정
- LH 방향과 현재 위치: 있음(일부) — 현재 위치는 가상 데이터 시험 단계. LH 방향은 공식 원문을 확인한 뒤 제안합니다
```

그 아래에 `화면에는 넣지 않고 말로 할 것`을 두세 줄로 적어 교육생과 확인한다. 예: "판단 기준값 일부가 임시값이라는 점은 화면에 넣지 않고 노트의 구두 보충에 둡니다."

같은 입력·같은 평가 조건의 전후 결과가 있으면 6장을 “같은 사례를 다시 처리해 보았습니다”로 구성할 수 있다. 비교할 자료가 없으면 현재 실제 결과물과 활용을 보여주고 전후 개선을 만들어 내지 않는다. 7장은 보고 판단에 중요할 때만 독립된 장으로 둔다. 평가 절차·통과율이 사업적 의미보다 큰 비중을 차지하면 결과물 장과 합치고 상세는 부록으로 보낸다.

외부 동향은 여러 회사의 사례로 한 흐름을 설명하는 구성이 좋다. 자료가 한 건뿐이면 그 범위에서 말하고 산업 전체의 추세로 일반화하지 않는다. 전략 연결과 다른 업무로의 확장은 근거가 충분하고 서로 다른 판단을 돕는다면 별도 장으로 나눌 수 있다. 지정이 없으면 표지를 뺀 본문 10~13장 안팎으로 제안하되 같은 내용을 반복해 장수를 채우지 않는다.

도식이 필요한 장(5장 전후 흐름, 9장 역할과 책임, 11장 단계)은 [도식 그리기](diagrams.md)를 따른다.

TR²Q는 별도 프레임워크 설명 장보다 업무 문제·흐름·결과·활용 범위에 녹인다. 확인된 구현과 아직 실행하지 않은 적용 제안을 구분하면서, 일의 변화가 조직에 왜 중요한지는 적극적으로 설명한다.

## 대화: 핵심 선택을 함께 좁힌다

### 빠진 숫자는 끌어낸다

전후 대비나 문제의 규모가 자료에 없으면 교육생에게 묻는다. 한 번에 하나씩, 답하기 쉬운 순서로 묻는다.

1. 실측이 있는지: "이 작업에 걸린 시간을 재 보신 기록이 있나요?"
2. 경험 추정: "재 보진 않으셨어도, 보통 한 건에 대략 얼마나 걸리나요?"
3. 구간 선택: "30분 안쪽, 1~2시간, 반나절, 하루 이상 중에 고른다면요?"
4. 바뀐 뒤도 같은 순서로: "지금 반나절이면, 검토표를 확인만 하게 됐을 때는 대략 얼마쯤 될까요?"

받은 값은 '담당자 경험 추정'으로 쓴다. 교육생의 추정에 '가정'이라는 말을 붙이지 않는다. 세 단계를 모두 물어도 없으면 그 숫자는 쓰지 않고, 어디서 셀 수 있는지(결재 이력, 로그, 티켓 기록) 구성 메모에 적는다. 사람 시간과 앱 처리 시간은 따로 받는다.

### 실제 화면을 요청한다

실행 화면이나 출력 파일 캡처가 없으면 첫 응답에서 요청한다. "검토표가 나온 화면이나 PDF 첫 장을 캡처해 주실 수 있나요? 개인정보와 실명은 가린 것으로요." 받지 못하면 실제 출력 값을 표로 옮기고 '발췌'라고 밝힌다. 화면을 꾸며 그리지 않는다.

표를 보여준 뒤 가장 중요한 질문 1~3개만 고른다. 빠진 숫자와 화면 요청이 있으면 그것을 먼저 넣는다. 남는 자리에는 예를 들어 이 과제의 중심을 “검색 시간 단축”과 “담당자마다 다른 판단 기준의 일관성” 중 어디에 둘지, 실제 활용 부서가 어디인지, 다음에 어떤 협조를 받고 싶은지 묻는다. 자료에 이미 나온 사실을 재질문하지 않는다.

교육생 답을 받으면 새 사실과 선호를 반영한다. 내용이 바뀐 장과 순서를 고치고 이유를 짧게 설명한다. 교육생이 수정한 핵심 방향은 이후 턴에도 유지한다. 전체 흐름을 바꾸는 답변이면 전체 표를 다시 보여주고, 표현만 고쳤다면 해당 행만 보여줘도 된다.

교육생이 과장된 효과를 원하면 그대로 실적으로 만들지 말고 근거가 허용하는 표현을 제안한다. 예: 업무 시간 실측이 없는 경우 “월 ○시간 절감” 대신 “담당자가 여러 문서를 대조하기 전에 확인할 항목을 한곳에 모았습니다”와 적용 후 확인할 효과를 구분한다. 기술적 한계는 화면에 늘어놓지 않고 구두 보충으로 정리한다.

## 제작: 합의한 이야기를 파일로 옮긴다

“좋아”, “그 방향으로 더 다듬자”만으로 파일 제작을 시작하지 않는다. “이 구성으로 최종 PPT 만들어줘”, “이제 파일로 줘”처럼 제작 요청이 오면 추가 승인을 반복하지 않고 만든다. 처음부터 사용자가 논의를 생략하라고 명시하면 그 지시를 따른다.

제작에 넘길 정보는 마지막 합의안의 핵심 메시지, 장 순서, 각 장의 주장·근거, 사용할 화면·도식, 현재 상태, 장별 구두 보충(화면에 넣지 않을 한계), 선택 서식이다. 파일 제작 도구가 장수를 맞추기 위해 새 주장이나 수치를 만들지 않도록 전달한다. 최종 제작 단계에서 처음 목차로 되돌아가지 않는다.

[기준 전개](base-flow.md)는 논리와 증거 배치의 참조다. 다른 교육생에게 해당 사례의 수치나 문장을 복사하지 않는다. 합의된 내용에 맞는 배치를 골라 LH 양식으로 만들고 전체 화면을 확인한다. 저장소 올리기나 다른 사람에게 공유는 사용자 요청이 있을 때 수행한다.
