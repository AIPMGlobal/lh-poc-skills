# 외부 동향과 전략 연결

외부 사례, 다른 기관의 흐름, 정부 정책과 LH 경영 방향, 다른 업무로의 확장을 다룰 때 읽는다. 최신 기업 사례나 전략은 작성 시점에 원문을 확인한다. 특정 기업의 목표나 성과를 고정 사실로 저장하지 않는다.

## 외부 동향은 제목, 기업 사례는 근거

장표는 `외부에서 나타나는 변화 → 관련 기업의 구체적인 활용 → 우리 과제에 주는 의미`로 구성한다. 제목에 특정 회사 이름을 내세우기보다 사례들을 통해 설명할 방향을 제시한다. 특정 회사의 심층 사례를 요청받았다면 그 요청을 따른다.

1. 과제에서 해결하는 업무 문제를 먼저 정한다. 계약 검토, 지식 검색, 장애 대응 등 문제 수준에서 관련 사례를 찾는다. 단순히 같은 모델이나 플랫폼을 쓴 기업을 모으지 않는다.
2. 공식 고객 사례·보도자료·공시·발표 자료를 우선한다. 공급사 고객 사례는 공급사의 설명이라는 성격을 보존한다. 홍보 자료의 주장을 독립적으로 검증된 성과라고 쓰지 않는다.
3. 서로 관련 있는 기업 사례를 여러 개 확보하면 공통 방향을 추린다. 일반적으로 두세 사례면 한 장에서 읽기 좋지만 숫자를 맞추려고 관련 없는 회사를 추가하지 않는다.
4. 각 사례는 `회사 / 실제 적용 업무 / 바뀐 업무 방식 / 확인된 범위`로 짧게 쓴다. AI 기능과 함께 도입된 일반 시스템·절차의 효과를 모두 AI 효과로 돌리지 않는다.
5. 마지막에 이번 과제가 참고할 부분을 적는다. 현재 범위와의 차이는 구두 보충에 둔다. 타사가 운영 중이라는 이유로 우리도 같은 수준에 도달했다고 결론내리지 않는다.

한 사례만 확인했다면 사례 소개로 쓴다. 공개 사례 몇 개로 업계 전체의 도입률·표준·필연적 방향을 증명하지 않는다. `공개 사례에서 확인한 방향`처럼 해석의 범위를 드러낸다. 동향이라고 말하려면 사례들이 실제로 같은 변화를 뒷받침하는지 확인한다.

### 장표의 구성 예

- 제목: 공개 사례들이 보여주는 업무 방식의 변화.
- 본문: 활용 방향 / 기업 사례 / 실제 업무에서 어떻게 활용하는지.
- 하단: 이번 과제에 적용할 방식.
- 각주·노트: 원문 URL, 발행일 또는 확인일, 출처 성격, 수치의 조건.

이는 구조 예시이며 모든 과제에 같은 제목·기업·도식을 복사하지 않는다. 외부 사례 장이 현재 보고에 새로운 판단을 더하지 않으면 생략한다.

## 안 하면 생기는 일: 공개 사고·제재 사례

위험을 말할 때 '문제가 될 수 있다'보다 실제로 일어난 일을 보여 주는 편이 설득력이 있다. 같은 업무 영역에서 공개된 사고·제재·정정 사례를 찾는다.

1. 과제가 막으려는 실패를 한 문장으로 적는다. 예: 계약 서류의 불일치, 공시 서류 오기재, 미승인 광고물 게시.
2. 감독·규제 기관의 보도자료, 공시, 주요 언론 보도에서 사례를 찾는다. 기관, 대상, 발표·보도 날짜, 규모(금액·건수)를 원문에서 확인한다. 검색 결과 요약만으로 쓰지 않는다.
3. 사례는 2~3건이면 충분하다. 대상, 날짜, 규모를 큰 글씨 한 줄로, 위반 내용을 작은 글씨 한 줄로 쓴다.
4. 우리 과제와 다른 점(위반 유형, 업무 범위)은 발표자 노트의 구두 보충에 적는다. 화면의 제목은 사례가 실제로 보여 주는 사실까지만 말한다. 그 사례의 금액을 우리가 막을 손실로 쓰지 않는다.
5. 확인한 사례가 없으면 이 장을 만들지 않는다. 내부 문제의 구조와 영향만으로 설명한다.

장표는 왼쪽에 '안 하면 생기는 일', 오른쪽에 '다른 기관의 대응'을 두고 아래에 우리의 적용점을 쓴다. 공공기관 과제라면 감사원 감사 결과, 국정감사 지적, 권익위 권고, 언론 보도가 주요 출처다.

## 날짜와 인용

발행일, 사례가 설명하는 적용 시점, 원문 확인일을 구분한다. 웹사이트 하단 저작권 연도를 기사 발행일로 사용하지 않는다. 발행일이 없으면 확인일만 기록하고 ‘최신 사례’라고 단정하지 않는다.

과거 사례도 현재 판단에 유용하면 사용할 수 있다. 당시 기술·운영 범위를 그대로 설명하고 현재도 운영 중이라고 추정하지 않는다. 검색 결과 요약만으로 숫자와 운영 상태를 확정하지 않는다. 원문에서 직접 확인하지 못한 인용은 쓰지 않는다.

외부 성과의 숫자는 우리 과제의 목표·예상 효과가 아니다. 비교를 위해 쓰면 대상·기간·업무 범위가 다름을 밝히고 금액·통과율을 그대로 전용하지 않는다.

## 정부 정책과 LH 경영 방향에 연결할 때

LH의 경영목표와 경영방침, 기관장 신년사와 취임사, 지속가능경영보고서, 공식 보도자료, 그리고 국토교통부와 정부의 공식 발표(국정과제, 공공기관 디지털 전환과 AI 활용 방침)에서 현재 관련성이 있는 방향을 확인한다. 특정 자료 유형을 전부 찾을 필요는 없다. 최신이라고 중요한 것은 아니므로 과제의 업무와 연결되는 원문을 고른다.

내부 분석에는 다음 세 줄을 분리한다.

- **정부와 공사가 추구하는 방향:** 공식 원문과 날짜. 이 과제가 공사 전체에서 어떤 가치와 관련되는지.
- **해당 본부와 부서가 수행할 역할:** 확인된 업무 범위와 책임. 공사의 방향을 부서의 공식 목표로 자동 치환하지 않는다.
- **과제의 기여 방식:** 누가 무엇을 다르게 할 수 있어 그 방향에 도움이 되는지. 현재 성과와 적용 제안을 구분한다.

찾아볼 방향의 예는 주거복지와 입주민 서비스, 업무 효율과 디지털 전환, 내부통제와 청렴, 현장 직원의 업무 부담이다. 이 목록은 찾아볼 방향일 뿐 근거가 아니다. 문구와 날짜는 공식 원문에서 다시 확인하고, 다른 발표 자료에서 옮겨 온 표현이면 그렇게 밝힌다.

표현은 `공식 방향 → 업무 변화 → 조직에 주는 의미`로 연결한다. 'AI 전환 방침에 부합'만 쓰거나 정책 문구를 과제 이름 뒤에 붙이지 않는다. 여러 방향을 한 장에 다 넣기보다 이번 과제와 가장 밀접한 항목을 고른다.

심사위원이 무엇을 좋아할지, 공식 평가표가 무엇인지 자료 없이 추정하지 않는다. 공식 자료를 확인하지 못했으면 방향 정렬을 확정하지 말고 과제의 일반적인 업무적 의미를 설명한다.

## 다른 영역으로 확장할 때

‘전 지역본부 확대 가능’ 같은 포괄적인 문구보다 공통 문제와 재사용 단위를 보여준다.

| 판단할 것 | 작성할 내용 |
|---|---|
| 공통 문제 | 현재 업무와 다음 업무가 공유하는 입력·판단·출력 구조 |
| 재사용할 부분 | 확인된 검색·비교·추출·근거 표시·검토 기록 등 실제 구성 |
| 바꿔야 할 부분 | 대상 문서, 규정·판정 기준, 권한, 시스템 연계, 사람의 책임 |
| 다음 적용 조건 | 시험 범위, 운영 주체, 자료 갱신, 예외 처리와 확인 기준 |
| 현재 상태 | 현재 적용 / 다음 시범 제안 / 장기 가능성 |

관련 영역을 많이 나열하는 것보다 한두 영역에 대한 구체적인 재사용 방식을 설명하는 편이 낫다. 확장 대상·우선순위·일정이 자료에 없으면 구성 논의에서 스킬의 제안이라고 교육생에게 밝히고, 교육생이 확인한 인접 업무만 화면에 싣는다. 실제로 연결되지 않은 앱들을 통합 플랫폼처럼 그리지 않는다.
