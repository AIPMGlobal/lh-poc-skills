# 기준 전개

신한DS 과정의 경영진 보고 작성 예시(준법감시 사전검토 과제)에서 다듬은 전개 방식이다. 그 예시는 우수 발표의 설득 장치(핵심 요약의 한 줄 전후 대비, 문제의 인원 규모, 공개 사례, 시연 순서, 확인한 결과 세 가지, 산식이 보이는 효과, 현재 위치가 보이는 단계와 결정, 닫는 선언)를 한 발표에 모았다. LH 발표도 이 전개 방식과 증거 배치를 그대로 쓴다. 특정 과제의 내용, 수치, 성과는 옮기지 않는다.

사용자가 다른 PPT나 특정 버전을 지정하면 그 참조가 우선이다. 양식만 바꿔 달라는 요청이면 이미 선택한 이야기, 핵심 논점, 근거, 도식의 역할을 유지하고 내용까지 새로 쓰지 않는다. 수정 범위 밖의 원본은 보존한다.

## 전개 방식 여덟 가지

1. **첫 장에서 업무 변화의 방향을 말한다.** Agent 이름이나 기능 목록보다 조직이 달리 일하게 되는 지점을 앞세운다. 표지에 현재 위치(구현, 시험, 적용 단계)를 표시하고, 바로 다음 장에서 한 줄 전후 대비로 결론을 말한다.
2. **문제가 다른 사람과 다음 업무에 미치는 영향을 보여 준다.** 단순한 작업량을 넘어 재검토, 인계, 판단 지연 같은 실제 연결을 설명한다.
3. **외부 동향과 현재 구현을 분리한다.** 다른 기관과 기업의 사례는 방향의 근거이며, 우리 구현 수준을 증명하는 자료가 아니다.
4. **실제 결과물을 핵심 증거로 놓는다.** 무엇을 확인할 수 있고 담당자가 어떻게 활용하는지 읽히게 한다. 놓친 사례는 화면이 아니라 노트의 구두 보충에 둔다.
5. **검증 결과는 확인한 것 세 가지로 보여 준다.** 실패와 미측정 건, 해석 범위는 구두 보충과 숨김 부록 한 장에 모은다.
6. **기능에서 업무 활용으로 한 단계 넓힌다.** 결과물이 담당자의 다음 행동에 어떻게 이어지는지 짚는다. 예: `분류 결과 제공 → 조치가 멈춘 세대를 먼저 확인 → 누락으로 생기는 뒤늦은 대응의 변화`. 과제마다 실제 행동과 다음 업무에 맞는 연결을 찾는다.
7. **확장, 방향, 운영을 각각 다른 질문에 답하게 한다.** 다른 업무에 무엇을 재사용하는지, LH 방향에 어떻게 기여하는지, 누가 확인하고 책임지는지 구분한다.
8. **다음 적용을 구체적으로 제안하고 한 문장으로 닫는다.** 현재 위치가 보이는 단계와 필요한 결정을 한 장에 두고, 마지막 장은 한 문장 선언으로 끝낸다.

위 순서와 장수는 모든 과제의 고정 목차가 아니다. 기존 발표를 다듬을 때는 사용자가 선택한 전개를 보존하고, 새로 구성할 때는 과제의 주된 가치와 근거에 맞춰 고르고 합치고 순서를 바꾼다. 장별 출발점은 [대화와 구성 제안](dialogue-workflow.md)의 열두 장 표다.

## TR²Q를 전개에 녹이는 자리

| 축 | 뜻 | 주로 들어가는 장 |
|---|---|---|
| T | 사람 작업 시간과 검토 부담 | 핵심 요약의 한 줄 전후 대비, 전후 업무 흐름, 조직 효과 |
| R | 업무 반복 빈도와 적용 규모 | 문제의 크기, 조직 효과의 산식 |
| Risk | 실패했을 때의 영향 | 문제가 생기는 지점, 안 하면 생기는 일, 운영 책임 |
| Q | 결과의 정확성, 완결성, 사용 가능성 | 실제 화면, 검증 결과 |

네 축을 표 한 장으로 따로 설명하지 않는다. 자료가 없는 축은 비워 둔다. 사용자가 TR²Q 표를 요청하면 현재, 개선 후, 조건을 나란히 둔 표로 만들고 수치의 성격은 출처 줄에 적는다.

## 표현과 증거의 경계

확인된 구현과 출력은 분명하게 말하고, 현업 적용 뒤의 효과는 실제로 재지 않았다면 기대 효과나 목표로 쓴다. 가치를 설명한다는 이유로 금액, 시간, 통과율을 만들지 않는다. '검증 미완료', '확인 필요', '보완 예정' 같은 말은 화면에 쓰지 않는다. 그런 내용은 발표자 노트의 구두 보충과 숨김 부록에 둔다.

새 과제에 적용할 때는 참조의 문장을 바꿔 끼우기보다 `누가 → 어떤 결과를 보고 → 무엇을 달리 하고 → 다음 업무에 어떤 변화가 생기는가`를 먼저 적는다. 이 연결이 이야기와 배치를 결정한다.
