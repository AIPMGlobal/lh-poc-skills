# 장표의 증거 배치

PPT 제작·전면 개편 시 읽는다. 일반적인 슬라이드 저작법을 대체하지 않는다. ‘소개·기능·품질·가치’ 항목을 예쁜 카드에 순서대로 채웠지만 결과와 논지가 보이지 않았던 실패를 줄이기 위한 지침이다.

## 먼저 고칠 것

- 사용자가 이미 선택한 참조 PPT가 있으면 그 버전이 우선이다. 서식만 변경할 때는 선택한 이야기·핵심 논점·근거·도식의 역할을 유지한다. [기준 전개](base-flow.md)의 적용 방법을 따른다.
- 장의 결론과 근거를 정한 뒤 배치한다. 남은 도형 칸을 채우기 위해 보조 가치나 기능을 만들지 않는다.
- 동일한 크기의 카드가 모든 내용을 동등하게 보이게 하면, 핵심 출력·비교를 크게 두고 설명은 보조 영역으로 옮긴다.
- 강조할 것은 일반적인 ‘생산성·품질·확산’ 구호보다 이번 자료가 실제로 보여주는 차이다.
- 전면 개선이 허용된 경우, 흰 바탕과 편집 가능한 텍스트·표·선으로 근거의 구조를 드러내는 구성을 우선 검토한다. 특정 색·서식을 보편 규칙으로 고정하지 않는다.
- 숫자가 없다는 이유로 장식용 수치·가짜 차트·외부 성과를 넣지 않는다. 실제 산출물과 근거가 정성적 가치의 증거가 될 수 있다.

## 근거별로 고를 배치

| 자료의 역할 | 권장 구성 | 피할 실패 |
|---|---|---|
| 같은 입력의 전후 비교 | 공통 입력을 위에 두고 기존·개선 출력을 나란히 배치. 실제 차이만 강조 | 입력·조건이 다른 출력을 직접 비교하거나 개선 쪽만 보여주기 |
| 결과물의 사용 가능성 | 보고서·답변의 핵심 영역을 크게 보여주고 짧은 주석으로 근거·범위·다음 행동 연결 | 화면을 읽을 수 없을 만큼 축소하고 기능 카드로 대신 설명 |
| 사람의 역할과 책임 | 업무 흐름에서 AI 산출물과 사람의 판단을 구분. 확인·수정·승인의 담당 표시 | 복잡한 도구 노드 전체를 업무 흐름처럼 제시 |
| 조직 가치의 설명 | 현재 기능 → 담당자의 행동 변화 → 조직 가치의 연결. 확인되지 않은 단계는 제안·기대임을 표시 | 산출물 생성에서 비용 절감·통제 완성·확산 실적으로 바로 이동 |
| 결론을 먼저 말할 때 | 한 줄 전후 대비를 크게 두고 아래에 확인한 결과·조건·요청 세 줄 | 서로 다른 단위나 구간을 한 줄에 놓기 |
| 문제의 크기 | 흐름 위에 되돌아가는 경로를 그리고, 관여 인원을 사람 모양으로 세어 보여 줌 | 근거 없는 인원·건수로 그림 채우기 |
| 위험의 실재 | 공개 사고·제재 사례를 날짜·규모와 함께, 옆에 대응 방식과 우리의 적용점 | 타사 금액을 우리가 막을 손실로 쓰기 |
| 검증 결과 | 증거(차트·화면) 옆에 확인한 결과 세 가지를 크게, 아래에 다음 확인 계획 한 줄 | 실패·미측정 건을 화면에 나열하기, 통과 기준을 숨긴 비율 |
| 닫는 장 | 한 문장 선언과 근거 세 가지 | 앞 장의 요약을 그대로 반복 |
| 다음 적용 판단 | 적용 범위·담당·운영 부담·확대 조건 중 실제 결정에 필요한 항목을 비교 | 실제 승인 요청이 없는 발표에 예산·인원 결재 장 만들기 |

이 배치를 모두 사용하거나 일정 장수를 맞출 필요는 없다. 하나의 장에서 충분히 설명되면 합치고, 구분이 필요한 근거만 별도 장으로 만든다. 표지·구조·범위 장에는 짧은 주제형 제목도 가능하다.

## 결과물을 근거로 보여줄 때

실제 화면은 출처·버전이 확인된 것을 사용한다. 보기 좋게 다시 그렸다면 ‘출력 요약’ 또는 ‘재구성’이라고 표시하고 의미를 바꾸지 않는다. 원본에 없는 상태 배지·승인 결과·사용자 행동을 덧붙여 실제 기능처럼 보이게 하지 않는다.

한계와 오류 사례는 화면에 넣지 않고 발표자 노트의 구두 보충에 적는다. 구두 보충에는 무엇을 놓쳤는지, 어떻게 보완할지, 그래서 사람이 무엇을 확인하는지를 말할 수 있게 쓴다. 화면에 싣는 결과는 실제로 확인한 것만 쓴다.

오류 원인 분석을 요청받았거나 교육생이 화면에 넣기를 원하면 상세 비교 장을 만들 수 있다. 그 밖에는 구두 보충과 숨김 부록에 둔다.

공식 전략이나 기술 역할도 업무 언어로 풀어 쓴다. 플랫폼·제품·내부 시스템 이름은 그 차이를 알아야 판단할 수 있을 때만 본문에 남기고, 나머지는 출처·노트에 둔다.

최종 점검은 글자 크기뿐 아니라 ‘무엇을 먼저 보게 되는가’를 확인한다. 한 장의 가장 큰 요소가 주장을 뒷받침하는 증거인지, 여러 장에서 같은 가치 문구가 반복되는지 살핀다.

## LH 양식으로 만들 때

색, 글꼴, 표지, 여백은 [LH 발표 디자인](design-system.md)을 따른다. 업무 흐름, 역할과 책임, 현행과 개선 비교, 단계는 [도식 그리기](diagrams.md)의 도형으로 그린다. 표와 도식과 글은 편집 가능한 상태로 둔다. 사용자가 제공한 더 구체적인 서식이 있으면 그 요청을 우선한다.

같은 양식으로 통일한다는 이유로 모든 장을 카드 세 개나 같은 열 수에 맞추지 않는다. 실제 출력은 큰 증거 영역, 업무 변화는 흐름과 비교, 조직적 의미는 인과 연결, 확장 제안은 재사용과 변경 부분이 보이는 구성을 고른다.

## 참고한 공개 자료와 적용 범위

- [McKinsey, Ready to board (2024)](https://www.mckinsey.com/locations/mckinsey-client-capabilities-network/our-work/strategic-and-change-communications/the-communications-exchange/ready-to-board-communicating-for-long-term-impact): 요약과 보고 목적을 명시하는 방식을 반영했다. 성과 공유·조언·결정 요청을 구분하며, 모든 발표에 결재 요청을 강제하지 않는다.
- [Penn State, Assertion–Evidence 체크리스트](https://www.writing.engr.psu.edu/AE_checklist.pdf): 핵심 메시지에 시각적 증거를 붙이는 방식을 반영했다. 모든 장을 문장형 제목으로 바꾸거나 특정 폰트 크기를 고정하는 규칙으로 사용하지 않는다.
- [Deutsche Telekom, AI Investor Day (2026), AI in Enterprise PDF 24·27·41쪽](https://www.telekom.com/en/investor-relations/publications/capital-markets-days/ai-investor-day): 기술·업무 방식의 변화에서 조직·고객 가치로 연결하는 설명을 참고했다. 해당 기업의 수치, 성과, 사업 규모를 다른 과제의 근거로 전용하지 않는다.

- 180 Degrees Consulting Oxford 슬라이드 서식: VS 대비, 인물 픽토그램, 화면 틀, 단계별 설명, 전면 선언의 배치를 참고했다. 원본의 로고와 문구는 쓰지 않았다.
- BCG, Melbourne as a Global Cultural Destination: 결론 띠와 사례, 접근, 영향 표의 배치를 참고했다. 원본의 내용과 수치는 가져오지 않았다.

- [BCG, AI-Powered R&D Executive Perspectives (2025)](https://www.bcg.com/assets/2025/executive-perspectives-ai-powered-r-and-d-14feb.pdf): PDF 4쪽의 행별 전후 비교, 9쪽의 개인·팀·조직별 가치 연결, 15쪽의 사람과 AI 역할 구분을 참고했다. 해당 기업의 수치와 성과, 브랜드 디자인은 다른 과제에 옮기지 않는다.
