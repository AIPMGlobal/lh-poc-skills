# LH 통합 PRD 작성 기준

모듈 Task별 PRD 1개. 기간은 3주. 작성일은 실제 작성일, 버전은 초안 v0.1을 기본으로 한다. 모듈 전체를 한 번 설명하고 Agent 정의는 실제 개수만 반복한다.

## Section 1 과제 개요

상단 과제명·모듈 Task 명·작성일·버전·구성원. 1.1 과제명, 매핑 프로세스(모듈 Task 및 대상 세부 Task 목록), 과제 오너. 1.2 무엇을 어떤 결과물로 개선하는지 1~2문장. 1.3 주관/협업 부서와 외부 파트너. 1.4 모듈리더와 Agent별 담당자. Agent 행은 ID·이름·담당 세부 Task를 함께 써서 매핑을 보존한다. 업무 수행자와 개발 담당자는 같다고 가정하지 않는다.

## Section 2 과제 배경 및 목표

2.1 세부 Task별 현행 방식·Pain Point → To-Be·AI 역할 → 소요시간. 현행과 목표를 구분하고 시간은 미제공이면 확인 필요. 2.2 정량/정성 기대효과. 실측이 없으면 측정 지표와 필요 정보만 제안하고 절감률을 계산하지 않는다. 2.3 사람 판단, 데이터 준비, 의존 관계 등 해당 업무의 실제 고려사항.

## Section 3 전체 흐름

순서 / 단계 / 수행 주체(AI 또는 Human) / 담당 Agent / Input / Output. 단계에 세부 Task 명을 넣고 Agent 칸에 ID와 이름을 쓴다. Human 승인과 다음 Agent에 넘기는 데이터를 표시한다. 규칙 기반 처리라면 AI(규칙 처리) 등 의미를 보완한다. 연결되지 않는 세부 Task를 억지로 하나의 순서로 만들지 않는다.

## Section 4 Agent 정의

Agent별 이름(담당 세부 Task 포함), 목적, 담당자, Trigger, Input, Output, 수행 단계, Human 개입, AI 기술 유형, 과정(구현 플랫폼 노드), 결과 화면 필요 여부. 원본 정의서의 Tool은 수행 단계와 과정에 매핑한다. 결과 화면이 불필요하다는 확인이 있으면 전달 방식과 함께 기록한다. 구현 플랫폼이 미정이면 `업무 수준: … / [확인 필요: 구현 플랫폼·지원 기능]`으로 쓴다. UI 상세는 후속 단계다.

## Section 5 외부 노드 요청서

5.1 Agent / 서비스·노드·외부 링크 / 용도 / 인증 방식 / 준비사항 / 대안. 도구 사용 희망과 실제 이용 가능 사실을 구분한다. 연동이 없다는 확인이 있을 때만 해당 없음을 쓴다. 내부망·화이트리스트·반입 조건은 LH에서 실제 사용하는 절차를 확인하여 작성한다.

## Section 6 범위 & 성공 기준

기본은 후속 멘토링에서 확정. 요청받으면 6.1 Must / Should / Out, 6.2 정량·정성 성공 기준과 정상/예외 시나리오를 작성한다. 반드시 **3주**를 기준으로 한다. 제공된 실제 확정 사항은 보존한다. 지표·측정법·합격 목표값을 구분하고 목표는 추정으로 확정하지 않는다.

## Section 7 UI 레퍼런스

선택 사항, 기본은 후속 멘토링에서 확정. 필요할 때 Agent / 기능 / 표시 데이터와 출처 / 실제 제공 레퍼런스 / Must·Should. 없는 화면이나 링크를 만들어내지 않는다.
